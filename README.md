# 会记

<img src="Resources/HuijiIcon.png" alt="会记图标" width="128">

会记是面向中文 Zoom 会议的原生 Mac 会议工作台。语音识别、会议资料及 AI 纪要均在本机处理，无账号、无会议上传。

源码仓库：https://github.com/Aronlele/huiji 。当前应用版本为 0.5.0；新增录音回放与文字定位、本地原文问答、四种纪要模板。环境准备沿用 0.4.4，说话人分析沿用 0.4.2 的修复。

本轮产品研究与验收方案：[听脑 AI 功能解析与会记改进设计](design/tingnao-review.html)。研究来自官方公开资料，竞品准确率和速度未独立验证。

产品展示页：https://aronlele.github.io/huiji/ 。网页源码位于 `docs/`，为无构建依赖的 HTML、CSS 与 JavaScript。GitHub Pages 使用 `main` 分支的 `/docs` 发布，提交该目录即可更新网站。下载入口指向测试版 Release；更新应用版本时同步更新网页中的版本和下载链接。

## 从源码构建

要求 Apple Silicon Mac、macOS 26 或更新，以及 Xcode Command Line Tools。在已安装命令行工具的 Mac 上运行：

```bash
git clone https://github.com/Aronlele/huiji.git
cd huiji
bash prepare-speaker-models.sh
bash build.sh
bash test.sh
open dist/会记.app
```

第一次准备说话人模型需要联网并下载约 88 MB，脚本固定版本并检查 SHA256；模型、运行库和编译产物不存入 Git。首次使用中文转写还需要准备系统中文识别模型。首次打开提供“模型与环境”准备向导：复用已有中文识别模型、系统本地 AI 或 Ollama/Qwen3；缺少时点击“一键准备”，自动下载系统中文识别模型及可选的本地 AI。说话人模型已随 DMG 打包。未配置 AI 时仍可使用转写和会议记录。

仓库包含应用源码、图标原图、构建脚本、单元测试与第三方许可说明；不包含个人会议、录音、声纹结果、模型或本机验证输出。音频集成测试依赖未随仓库发布的本机测试资料，范围见 `Tests/README.md`。图标由内置 imagegen 生成，设计提示见 `design/icon-prompt.txt`，构建时从 PNG 生成标准 macOS 图标尺寸。

## 使用

打开 `dist/会记.app`，先新建会议，填写名称，再开始转写。电脑播放的声音始终独立采集，麦克风可在转写中随时开关。Zoom 静音只影响 Zoom，不会替代会记里的麦克风开关；使用外放时建议关闭会记麦克风，避免两路重复。

- **会议库**：全文搜索、重命名、收藏、文件夹归类。删除后进入最近删除，可撤销或恢复；永久删除需要确认，不会自动清空。
- **转写**：暂停、继续、结束、计时、音量；逐段校对、保留识别原文、重点标记、来源筛选、会议内查找、复制。
- **录音回顾**：点击转写时间从该段回听，拖动进度、前后跳转 10 秒、0.75–2 倍速、声音来源切换；播放段落高亮并可跟随定位。暂停录制后可回听，继续录制前自动停止。缺少音频的历史会议保留文字。
- **会议问答**：在“问答”输入问题（最多 500 字），本机 AI 查阅本场原文和笔记，回答附逐字引文。点击引文定位原文，问答随会议保存，支持删除单条；原文/笔记变化后提示核对。找不到可核验依据时不显示肯定答案。长材料逐段查阅全部内容，显示进度并可取消，不截去后半场。
- **笔记与待办**：议程和随记自动保存；待办包括负责人、截止时间及完成状态，可编辑。
- **纪要**：工作会议、项目评审、访谈沟通、课堂笔记四种场景，选择按会议保存；切换不覆盖旧纪要，重新生成才应用。结束实时转写后自动整理；历史会议可手动生成或重新生成。结果可校对，建议待办附原文短句，确认后才加入列表。
- **说话人**：新录制或导入的会议，会后在本机分离声音。点击说话人姓名可整场改名，段落上的姓名菜单可纠正归属、新增说话人或标为未确定。可指定人数重新分离；人数选择、姓名和人工纠正均保留，TXT/Markdown/SRT 导出含姓名。
- **导入与导出**：选择本机音频文件离线转写；导出 TXT、Markdown、SRT。旧版纯文本缺少结束时间，保留完整原文，支持 TXT/Markdown，不伪造准确字幕。

资料保存于 `~/Library/Application Support/local.huiji.meetingtranscriber/Meetings/`。每场会议为一份 JSON、一份 UTF-8 TXT，以及 `Audio/会议UUID/` 下的本地音频。音频采用 16kHz 单声道 WAV，每路每小时约 115 MB；两路分别保存，麦克风关闭后只继续保存电脑声音。暂停/继续追加独立音频片段，不覆盖已有录音。导入时保留本地音频副本，原文件不移动。最近删除可恢复全部资料，永久删除才移除该会议的文本与音频。备份应复制整个目录。

旧会议未保存音频，不能补做自动分离；有结构化段落的可手动指定姓名，旧版纯文本保留原样。说话人标签只在本场会议内使用，不建立跨会议声纹身份库，也不能自动取得 Zoom 参会人的真实姓名。

## 本地说话人模型

0.4.2 随应用打包 sherpa-onnx 1.13.8、pyannote segmentation 3.0、Silero VAD 和中文 ERes2NetV2（约 20 万说话人训练）ONNX 模型，固定依赖下载约 88 MB。本轮模型与运行库未更换。处理完全在本机 CPU 运行，无 Python 环境、云接口或账号。模型与许可证来源在 `Resources/SpeakerModels/`。

保留每个声音起止与停顿边界，声音检测与停顿检测取并集，避免安静接话被直接删除。不到 200 毫秒及混合片段保留时间、不独立提取声纹；输出前检查非有限数值，异常向量不再使整场分析失败。较长发言提取完整声纹并做平均连接聚类，短发言结合稳定声纹中心和可信上下文匹配已有身份；自动模式下孤立、短暂的分组不直接计为新人。证据不足或真正的多人重叠仍保留未确定。

以词时间分配文字，同一身份的重复时间只计一次；静音后被识别时间提前的句首单字，仅在后续长句归属明确、没有竞争声音时补偿，独立短句不套用。不同声音之间限制边界补偿，同一人被自动拆碎的相邻段落重新合并；手动指定和已编辑段落保持独立。指定实际发言人数仍可用。

本机回归覆盖五份输入：相近双人四轮、相同声音不同内容六轮、单人三轮、短句交替六轮，以及作者公开中文四人示例的十个参考片段。0.4.2 自动人数分别为 2、2、1、2、4，主要发言归属均符合这些输入的参考。原双人样本在同一份冻结的系统 ASR 词时间下，旧版指定两人的归属错误为 21/119 个中文字符，新版自动模式为 0/119；这不衡量文字识别错误，也不是 Zoom 会议准确率。公开示例参考来自作者模型输出，合成参考来自声音文件拼接，均非独立人工标注真实会议。结果在 `verification/speaker-upgrade-results.json`。

另用相同的三段 AliMeeting 真人中文远场会议（每段三分钟，共九分钟）及独立人工标注复测。原双人样本的严格时间错误率从 65.5% 降至 16.8%，清晰交接匹配从 3/13 增至 10/13；原来分析失败的普通四人、高抢话四人样本现可完成，自动模式错误率分别为 28.9%、76.1%。自动人数为 2、4、4，但 ≤1 秒短句的过半时长归属正确数仍仅为 3/15、2/16、3/47；双人短句正确数未提高。评分计入未确定、漏声、额外声音及抢话，不排除困难片段。三段同时用于本轮开发与回归，不能代表独立盲测、整个数据集或真实 Zoom 准确率。详细报告与原始结果在 `verification/real-meeting/after-0.4.2/`，运行 `python3 verification/real-meeting/compare.py` 可重新评分生成对比报告。

声音相近、发言极短、外放回声、背景噪声与多人重叠仍可能出错，保留人数提示、未确定及人工校对。真实会议中的短接话和多人抢话尚未达到可靠程度，当前未实现同时讲话的多人各自完整出文字；自然人长会议和真实 Zoom 设备环境仍未验证，不承诺免校对。超过 8192 个可建立身份的发言片段时停止并提示分段导入，不静默截断；原音频、转写和已有归属保留。原始音频仅用于本地推理，结束/取消清理临时合并文件；本地保存副本支持重试。

## 首次安装与模型准备

DMG 安装：拖入 Applications，然后打开会记。拖拽安装不会执行脚本，模型准备在首次打开的应用内完成，无需终端或管理员权限。

- 自动检查四项：系统中文识别、包内说话人模型及运行库、本地 AI 运行环境、中文纪要模型。已有环境跳过下载；下载前再次检测。
- 中文识别模型由 Apple 的 AssetInventory 下载并共享，系统已安装时直接复用，显示系统提供的下载进度。
- 优先使用支持中文的系统本地 AI。否则复用运行中的本机 Ollama，或检测 Applications、用户 Applications、Homebrew、已注册的 Ollama、PATH 与会记自己的运行环境。
- 没有 Ollama 时下载固定的官方 0.40.3（约 206 MB），校验 SHA256 和官方 Developer ID 签名后安装到 `~/Library/Application Support/local.huiji.meetingtranscriber/Runtime/Ollama.app`。不会覆盖用户已安装的 Ollama，不添加开机启动项，不修改系统 Python 或 Homebrew。
- 中文纪要模型通过本机 Ollama 的 `/api/pull` 下载 `qwen3:4b-instruct`，显示各文件下载进度，约 2.5 GB，建议预留 6 GB 空间。已有相同本地模型跳过；云模型不算就绪。继续使用 Ollama 原有模型目录（默认 `~/.ollama/models`）。
- 可以停止或重试，已完成的组件保留；Ollama 模型下载支持续传，运行环境压缩包中断后重试会重新下载。下载失败不会删除会议或覆盖原有环境。
- 可以取消“同时准备自动纪要与待办”，先使用转写；从菜单或侧栏“模型与环境”随时补齐。转写或分析进行中不运行安装。

安装时需要联网获取模型与官方运行环境；转写、说话人分析和纪要生成在本机完成。首次麦克风与电脑声音权限在实际开始采集时由 macOS 请求。

## 本地 AI

优先使用支持中文的系统本地语言模型；不可用时使用官方 Ollama 与 `qwen3:4b-instruct`（约 2.5 GB）。中文语音识别与摘要模型相互独立。

AI 固定连接 `http://127.0.0.1:11434`，拒绝重定向与系统 HTTP 代理，不使用云端模型；会记启动的服务明确关闭 Ollama 云端功能。模型首次下载需要联网；纪要和问答生成不需要上传会议。AI 回答可能误解、遗漏，引用通过逐字校验不代表推理绝对正确，仍需核对。会记可按需启动官方 Ollama CLI 的本地服务；自行启动的服务随会记退出，已有外部服务则保持运行。不增加开机启动项。模型不就绪或生成失败会明确提示并保留会议原文及原有纪要。

长会议分段整理后逐级汇总，涵盖全部输入，不静默截断。生成时合并完全相同的连续段落，并保留各段的任务结果；会议原文保持完整。待办必须带输入中存在的原文短句；仍可能误解语义，需要人工校对。待确认建议也保存到会议中。

## 环境与验证

要求 Apple Silicon、macOS 26 或更新，且系统中文识别模型可用。首次准备中文识别模型需要联网。应用使用 CoreAudio 私有进程音频 tap、AVAudioEngine 和系统 SpeechAnalyzer，不更改默认输入输出设备，不安装虚拟声卡。

首次构建可运行 `bash prepare-speaker-models.sh` 从官方来源下载并按固定 SHA256 校验模型和运行库；`bash build.sh` 生成本机 ad-hoc 签名的应用，包含独立本地推理进程和运行库签名。`bash test.sh` 执行转写、存储、说话人标签和受控设备音频归档测试，不采集真实音频、不访问真实会议。`bash check-speakers.sh` 使用固定的公开/合成音频进行实际模型验收；`Tests/MeetingTranscriberTests/SpeakerIntegrationTests.swift` 使用两种系统声音生成的中文测试会议，验证实际模型、系统 ASR、词时间对齐、原文完整、改名与人工归属的重分析保存导出，以及取消终止推理。验证输出在 `verification/`。`Tests/MeetingTranscriberTests/LocalAITests.swift` 是需要已安装模型的本机 AI 集成测试，使用合成会议资料。

竞品研究、设计决策与验收范围见 `design/product-design.html`。来源标签与说话人独立保留。0.5.0 已补齐音频回放、单场原文问答与纪要模板，详见 `design/tingnao-review.html`；日历、跨会议问答与团队协作尚未实现。
